# Pelada — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Site mobile first para a pelada de quarta: lista com mensalistas e fila de diaristas, sorteio equilibrado, anotador ao vivo, ranking e painel admin.

**Architecture:** Next.js (App Router) com Server Actions e Postgres via Drizzle. As regras do jogo ficam em `src/domain/` como funções puras (sem banco, sem relógio: `now` sempre chega por parâmetro). As ações do servidor carregam dados, chamam o domínio e gravam. Estado da lista e estatísticas são **derivados** de registros brutos (presenças, lances, resultados), nunca guardados como contadores.

**Tech Stack:** Next.js 16, React, TypeScript strict, Tailwind CSS, Drizzle ORM + drizzle-kit, Postgres (Neon na Vercel; PGlite nos testes), `jose` (cookie de sessão assinado), `node:crypto` scrypt (hash de PIN/senha), Vitest, Playwright, pnpm.

**Spec:** `docs/superpowers/specs/2026-11-04-pelada-design.md`

## Global Constraints

- Só uma pelada; sem multi-tenant. Interface em pt-BR.
- Fuso **America/Recife**, sem horário de verão: offset fixo `-03:00`.
- Pelada: **quarta 20:30–22:30**. Lista abre **segunda 00:00**. Prazo do mensalista: **quarta 14:00**.
- **16 vagas**; no máximo **16 mensalistas** por mês; **4 times de 4**.
- Nota: **0 a 5, passo 0,5**; jogador novo começa com **3,0**.
- PIN: 4 dígitos, padrão **`1234`**, troca obrigatória no primeiro acesso; **5 erros seguidos → bloqueio de 15 min**.
- Sessão do jogador: cookie `pelada_jogador`, **365 dias**. Sessão admin: cookie `pelada_admin`, separado (as duas coexistem no mesmo aparelho).
- Partida: termina com **3 gols** ou **8:00**; cronômetro corre direto; **sem gol contra**; placar = soma dos gols dos jogadores do lado.
- Pontuação: **vitória 3, empate 1, gol 1, assistência 1**. Desempate: vitórias, depois gols, depois menos jogos.
- Todo o site exige login (jogador ou admin), exceto `/entrar` e `/admin/entrar`.
- Lista e anotador se atualizam por nova consulta a cada **5 s** enquanto abertos.
- **Toda tela** é desenhada com as skills `impeccable:impeccable` e `taste-skill:design-taste-frontend` antes de codar e revisada por elas (critique/polish) antes do PR. O PR lista o que apontaram e o que foi corrigido. Contraste alto (uso ao ar livre, à noite).
- Git flow: um `feature/*` por parte a partir de `develop` → PR para `develop` → revisão → merge. Commits pequenos (`feat:`, `test:`, `chore:`, `docs:`). **Sem atribuição de IA** em commits ou PRs.
- Depois de cada parte com servidor de dev ou navegador headless: encerrar os processos.

## Review Focus

1. **Corridas na lista:** dois diaristas entrando na fila no mesmo segundo, ou um mensalista removendo enquanto o diarista confirma. A ordem tem que ser estável (desempate por `id`) e confirmar fora da lista principal tem que ser recusado. → teste na Task 6.
2. **Toques duplos no anotador:** dois toques rápidos em GOL geram dois lances (comportamento esperado), e Desfazer remove só o último, mesmo com dois admins na mesma partida. → teste na Task 11.
3. **Virada de mês no ranking:** a pelada de quarta 30/09/2026 que termina às 22:15 em Recife fica registrada como 01/10 01:15 em UTC, e tem que contar em setembro. → teste na Task 13.
4. **Jogador trocado de time no meio da noite:** as estatísticas das partidas antigas não podem mudar quando o time é editado depois. É por isso que cada partida guarda a foto do elenco em `partida_jogadores`. → teste na Task 11.
5. **Menos de 16 presentes no sorteio** (ex.: 13): os times saem com tamanhos 4/3/3/3 e continuam equilibrados, sem erro. → teste na Task 9.

## Modelo de dados (Task 2 cria; todas as outras usam)

| Tabela | Colunas |
|---|---|

| `presencas` | `id`, `pelada_id`, `jogador_id`, `tipo` enum(`M`,`D`), `status` enum(`pendente`,`confirmado`,`removido`), `entrou_em` timestamptz, `atualizado_em`; único (`pelada_id`,`jogador_id`) |
| `times` | `id`, `pelada_id`, `cor` enum(`azul`,`laranja`,`verde`,`preto`), `ordem` int |

| `partida_jogadores` | `partida_id`, `jogador_id`, `lado` enum(`A`,`B`) — foto do elenco no início |
| `lances` | `id` serial, `partida_id`, `jogador_id`, `tipo` enum(`gol`,`assistencia`), `criado_em` |

**Interfaces:**
- Produces (`tempo.ts`):
  - `proximaQuarta(now: Date): string` (data `'YYYY-MM-DD'` da quarta desta semana; depois de quarta 22:30 passa para a próxima)
  - `aberturaLista(dataQuarta: string): Date` (segunda 00:00 -03:00)
  - `prazoMensalista(dataQuarta: string): Date` (quarta 14:00 -03:00)
  - `inicioJogo(dataQuarta: string): Date` (quarta 20:30 -03:00)
- Produces (`lista.ts`):
  ```ts
  type Presenca = { id: number; jogadorId: number; nome: string; tipo: 'M' | 'D'; status: 'pendente' | 'confirmado' | 'removido'; entrouEm: Date }
  type ItemLista = { jogadorId: number; nome: string; tipo: 'M' | 'D'; confirmado: boolean }
  type EstadoLista = { aberta: boolean; cancelada: boolean; principal: ItemLista[]; fila: ItemLista[]; vagas: number }
  calcularLista(input: { presencas: Presenca[]; dataQuarta: string; estadoManual: 'aberta' | 'fechada' | 'cancelada' | null; now: Date; vagas?: number /* 16 */ }): EstadoLista
  podeConfirmar(estado: EstadoLista, jogadorId: number): boolean   // só quem está em `principal` e ainda não confirmou
  ```
- Regras de `calcularLista`, na ordem:
  1. Ignorar `removido`.
  2. Mensalista `pendente` depois do `prazoMensalista` → fora (não entra nem na fila).
  3. `principal` = mensalistas restantes (ordem `entrouEm`, depois `id`), completados pelos diaristas na ordem `entrouEm`, depois `id`, até `vagas`.
  4. `fila` = diaristas que sobraram, na mesma ordem.
  5. `aberta` = `estadoManual === 'aberta'` ou (`estadoManual === null` e `aberturaLista <= now < inicioJogo + 2h`). `cancelada` = `estadoManual === 'cancelada'`.

```ts
type PartidaEncerrada = { id: number; peladaData: string; encerradaEm: Date; resultado: 'A' | 'B' | 'empate'; elenco: { jogadorId: number; lado: 'A' | 'B' }[]; lances: { jogadorId: number; tipo: 'gol' | 'assistencia' }[] }
type Periodo = { tipo: 'geral' } | { tipo: 'ano'; ano: number } | { tipo: 'mes'; ano: number; mes: number }
```

- Ordem: pontos ↓, vitórias ↓, gols ↓, jogos ↑, nome ↑.

  - Pelada `'2026-09-30'` com `encerradaEm` `2026-10-01T01:15:00Z` entra em `{tipo:'mes', ano: 2026, mes: 9}` e não entra em `{tipo:'mes', ano: 2026, mes: 10}` (Review Focus 3).
  - `presencas` conta quartas, não partidas.
